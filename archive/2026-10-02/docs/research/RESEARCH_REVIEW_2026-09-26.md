# FLUX 独立调研复评与计划采纳

日期：2026-09-26。结论：**采纳核心路线，修正证据与实验设计后并入计划；不整体照单执行。** 本文评审 `docs/claude_research/2026-09-26/` 的五份报告，对照现有规划、当前源码、依赖源码和历史 MIDI，并复查影响路线选择的一手来源。原调研保留原样，便于追溯。

当前执行顺序以 [RESEARCH_RESET](../RESEARCH_RESET_2026-09-26.md) 为入口，产品行为和验收以 [DAW_SPEC](../DAW_SPEC_2026-09-26.md) 为准。本文记录采纳理由与实验修订；原 [EXPERIMENT_PLAN](../claude_research/2026-09-26/EXPERIMENT_PLAN.md) 的 E0–E7 是实验设计素材，冲突处以本文为准。所有新增功能仍待实现。

## 1. 评审判断与采纳范围

这轮调研有实质增量：它找到了首个 control 被裁剪的源码路径，将稀疏输出拆成可证伪假设，补充了按任务筛选的候选，并把 DAW 行为写成了可验收用例。它明确区分源码、产物、作者声明和推断，足以支持下一步工程规划；没有新的模型推理、盲听或本机性能结果，不能作为选型胜负的证明。

| 内容 | 决定 | 并入后的要求 |
|---|---|---|
| 和弦轨作为项目对象；角色优先生成 | 采纳，并按用户要求强化 | MIDI 和弦自动显示；手动根音＋类型；上下文级数／进行；确认后的同一和弦轨驱动各生成器。见 DAW_SPEC §4.4–4.7、§8 |

## 2. 需要修正或收紧的结论

### 2.1 确定性缺陷成立，听感因果仍待实验

- 本机使用已安装的 `anticipation` 复算：`ops.max_time(controls)` 为 **7.0 s**，源旋律结束于 **8.0 s**；`sample.generate()` 将 `DELTA=5` 传给 `seconds=False` 的 clip，实际裁掉前 **0.05 s**，14 个 controls 只保留 13 个。不能把配置中“5 秒 anticipation”的注释与这次 clip 的实际单位混淆。
- 采样器确实在新 onset 达到／超过终点时停止。这是可观察的停止机制；是否解释 medium 的稀疏、如何修改才不破坏分布，尚未证明。**先记录停止原因，保持原策略作为对照**；屏蔽越界 token 和延长窗口只能作为实验分支，必须有事件／耗时上限。
- 原报告将这些列为“杂乱的确定性原因”过强。可以确认信息丢失与边界不符合产品要求；各因素对听感的贡献需要分离对照。网页 stub 不能代表 AMT，也不能据此断言用户所有历史试听都来自 stub。
- `generate_events()` 回退 CPU 后，`pipeline.run()` 仍写最初的 `device` 变量。这证明旧记录**可能错误**，不证明某次历史运行确实发生过回退。

### 2.2 旧混合 MIDI 只能支持有限的生成来源判断

本机复核五份伴奏产物：力度均为 72、`ticks_per_beat=50`、没有 tempo／拍号事件；两份受限产物没有 program 32 贝斯。按原报告的“channel＋pitch＋onset”口径可复现剩余音符数 **64 / 62 / 50 / 12 / 4**，但该口径不是可靠的来源标记。

进一步加入 duration 匹配并按 FIFO 配对 note-on/off，`ab_small_constrained.mid` 的原旋律 **G4、起点第 6 拍、时值 2 拍**无法原样匹配；同音高重叠使其配成 15 拍，另一条 G4 的结束事件在第 8 拍。不同配对策略会改变音符归属和时值统计。这个现象不等于已经证明原音被删除；它说明混轨文件不足以唯一还原来源。原报告的生成音数、冲突数和长音数应注明匹配假设，不能直接作为新基准真值。

新适配器必须在混合前保留候选事件、稳定来源 ID 和源轨快照；为同音色、同音高、相同 onset、重叠时值建立边界用例。旧产物只做历史诊断。

### 2.3 模型与许可结论

- **AMT 的 MIREX 证据有用，但不是优于所有模型的证明。** 原文对应钢琴续写，各队从每个 prompt 的 8 个样本中挑 1 个；14 人完成全部评价。AMT 与 RWKV 在表中四项属于同一显著性组，不能把三个均值最高解释成统计显著胜出，更不能外推到本机单次流行伴奏。[原论文 §3](https://arxiv.org/html/2509.12267)
- **CA2 改称“训练数据来源声明较清晰，权重条款待核”。** README 声称使用公共领域及宽松许可 MIDI，并要求阅读下载包里的许可／免责声明；尚未核验下载包，不采用“许可最干净／可直接产品化”的结论。[官方仓库](https://github.com/m-malandro/composers-assistant-REAPER)
- **MIDI-GPT 的代码和权重许可分开。** 官方权重卡确为 CC-BY-NC-4.0；不能泛称“演示都允许”，要看具体用途是否满足条款。yellow 优先研究；prism／expressive 的文档与文件版本不一致时锁定具体 revision 和文件。[模型卡](https://huggingface.co/Metacreation/MIDI-GPT)、[模型文档](https://raw.githubusercontent.com/Metacreation-Lab/MIDI-GPT/main/docs/models.md)
- **Pop1K7 补证可采纳。** Zenodo API 的 `metadata.license.id=cc-by-4.0`、发布日期 2024-07-31 已复核。发布者条款不证明所有底层作品权利均已覆盖；同样，未见授权证据应写“未核实”，不武断写成“确定未授权”。[数据页](https://zenodo.org/records/13143907)、[元数据](https://zenodo.org/api/records/13143907)
- AccoMontage2 可加入流行钢琴织体候选，4/4 和 4／8 小节乐句限制按任务筛选；不把代码 MIT 扩写为检查点许可已清楚。[官方仓库](https://github.com/billyblu2000/AccoMontage2)

### 2.4 浏览器与和声分析边界

- “某兼容列表没有 Safari”不能推导为库不支持 Safari；`spessasynth_lib` 当前 README 声称支持现代浏览器。采纳尽早实测，不预先把 Safari 用户降为不完整乐器目录。若启用替代引擎，仍须达到本阶段的完整 GM 与独立通道门槛。[库说明](https://github.com/spessasus/spessasynth_lib)
- 不直接照搬 `currentTime - outputLatency` 作为通用录音补偿。事件时间、渲染时钟、输出设备时钟要映射；`getOutputTimestamp()` 提供 `contextTime/performanceTime` 对应。敲拍得到的是用户与设备综合偏移，不能标作纯设备延迟，也不能与已有补偿重复相减。保留原始时间并单独校准。[MDN](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)
- **音集合 → 和弦名、和弦序列 → 调性／级数、旋律 → 配和声是三个任务。** Tonal 能返回多个可能的和弦名；music21 的 Roman numeral 分析需要调性上下文。它们可作为实现候选或对照，尚未选定依赖；不能用一个库调用宣称已经解决上下文推断。[Tonal](https://tonaljs.github.io/tonal/docs/groups/chords)、[music21](https://music21.org/music21docs/usersGuide/usersGuide_23_romanNumerals.html)

## 3. 实验计划的执行修订

保留原 E0–E7 编号，采用以下收敛顺序和修正。数值门槛是待预注册的工程目标，不能当作模型已有成绩。

| 阶段 | 当前计划 | 完成条件 |
|---|---|---|
| E0 | 先做 T1–T12 的契约、转换、来源和日志；T2 须验证首 controls 真正进入采样上下文，而不只计算 clip 后数量；T12 先加观测，不预先替换停止策略 | 假采样器 dry-run、确定性回归通过；旧逻辑能重现缺陷；历史文件 hash 不变；不要求下载模型才能验收 |
| R0 | 两种原创 pattern 风格 × 贝斯／鼓／铺底；先用手动确认的和弦，再接 MIDI 识别建议 | 和弦根音／指定低音、时值、角色、轨道隔离、空白和 N.C. 行为通过 DAW 验收；单独记录模板感与修改成本 |
| E1a | 6 段 × 3 seeds；先保持自由乐器验证 C0→C1→C2 的时间条件，再选贝斯作为首个目标测试单角色、停止策略、和弦条件和后处理 | 每个成对比较只改变指定因素；先测单次耗时，再列出扩展组合与总预算 |
| E1b | 仅对 E1a 暴露的问题扩展到其他角色；分别评价力度和时值处理 | 能指出哪个改动改善什么，保留负结果；不默认启动约 486 次生成的大矩阵 |
| E2 | 同条件下比较 R0、修复 AMT、MIDI-GPT；CA2／RWKV／AccoMontage2 在适配与许可明确后按需加入 | 按任务报告有效率、修改成本、与 R0 的偏好和实测延迟；无人达标则继续 R0，模型保留实验标签 |
| E2b | 钢琴续写单独比较 Aria 与 AMT；RWKV-piano 为可选对照 | 独立任务结论，不据此决定鼓／贝斯生成器 |
| E3–E6 | 有固定候选与盲听标签后再做排序；路由／表示探针可独立准备；LLM 规划对比直接音符生成 | 同一候选池、同一用户要求，中英文分层，允许全部拒绝；记录 API 版本、外发字段、延迟和费用 |
| E7 | 明确失败属于风格问题、基座已选定且数据可用后才进入适配 | 按作品分割，保持评估集独立；无收益则停止 |

原实验设计须同时修正以下六点：

1. **重试不等于原始成功率。** C3 的“最多重采样 2 次”须与单角色控制分开。逐次记录 first-attempt 与重试后可用率，重试耗时全部计入交互延迟。
2. **组合改善不能自动归因。** C7 合并多个改变，只能证明组合有效；“主要来自管线”的结论需移除单因素对照。top_p 与和声质量也不要求单调关系。
3. **和弦条件要有相同预算。** 分开比较无和弦／人工真值和弦／自动识别后确认的和弦。固定相同的 voicing、条件轨数量和密度；记录各模型实际收到的条件，不能把不支持条件的模型标作已遵循。
4. **音乐特征不是一律硬错误。** 三全音、经过音、借用和弦、切分和长铺底都可能合理；只按角色／风格记录风险。`C7` 自带三全音，不能因此被硬过滤；铺底跨小节时用有效发声覆盖率补充 onset 密度。同轨同音高重叠属于播放／配对策略检查，不与越界 MIDI 音高混为一类。
5. **工程边界必须完全成立。** 应用到项目的候选 onset 在 `[startTick,endTick)`，note-off 不超过选区终点；原轨不变、轨道合法、音符合法均为 100%。原始模型越界率另记；不能以 `in_range≥99%` 接受剩余越界音。
6. **统计单位按作品隔离。** 同作品的多个 seeds／角色／评分不是独立样本；成对比较先按作品汇总，或按作品聚类 bootstrap，报告作品数、候选数、评分者数、平局。原“至少 40 对”不等于 40 首独立作品；小样本 CI 不稳定时标探索性，不强行宣称胜出。候选总量应按作品×任务×系统×seed 明算，不能把 20×5×3 每系统 300 个候选写成所有系统共 300 个。

训练语料污染检查只能覆盖实际可取得的参考语料；没有完整语料时写“未能全面核验”，不能声称已经排除。API 试验、本机模型推理和训练均未在本轮执行。
