## 4. 和弦进行没分析出来（第 11 项）

**诊断。**用用户的项目逐一核对草稿列出的 4 个可能原因：

1. 只分析选中的一条音高轨：不是原因。4 个和弦都已确认（来源是钢琴轨），级数与进行分析读的是已确认和弦，与当前选中哪条轨无关。
2. 实时录的和弦有连奏重叠或琶音：不是原因。第 4 个 F/C 是实时弹的，三个音相差约 60 tick 先后按下，分段时忽略了不足 1/16 的片段，仍识别为 F/C。
3. 调性证据不足不给级数：不是原因。推测调性 F 大调（得分 1.268，第二名 C 大调 1.142，差 0.126 > 0.05），级数行正常显示 V⁶、ii⁶₄、I⁶₄、I⁶₄。
4. **进行不在命名模式表里：这是原因。**V⁶–ii⁶₄–I⁶₄ 不匹配任何命名进行，而“级数与进行”面板只列命名进行，于是整块空白，看起来像没分析。另外两个相同的 F/C 连在一起，本身也会打断模式匹配（例如 ii–V–V–I 认不出 ii–V–I）。

**修复。**

- 分析结果新增 `runs`：每段连续和弦（N.C. 或超过一小节的空白断开）都给出完整级数序列和数字级数，连续相同的和弦算一个和声。面板始终先列出这一行（“整段进行”），没有命名进行匹配时再说明一句，不再空白。
- 模式匹配和副属和弦判断都先合并连续相同的和弦：ii–V–V–I 能认出 ii–V–I；C–D7–D7–G 的两个 D7 都读作 V7/V，只报一次副属和弦。
- 用户的这段现在显示：**V⁶–ii⁶₄–I⁶₄（5–2m–1）· F 大调（推测）**。

**测试。**`frontend/tests/fixtures/user_a02_same_program.flux.json` 是用户文件的原样副本；`tests/analysis.test.js` 新增 4 项：用户项目在推测调性下的完整进行、在手选 C 大调下读作 I⁶–v⁶₄–IV⁶₄ 并标出借用和弦、连续重复和弦的模式与副属判断、无命名进行时仍给出整段级数。

关于调性的说明：C/E–Gm/D–F/C 也可以听成 C 大调（I–v–IV，Gm 借自 C 小调）。自动推测选 F 大调，是因为三个和弦在 F 大调里都是自然音、并且结束在 F 上。如果你听到的是 C 大调，在“调性”里手选即可，和弦与音符都不会被移调。
