# FLUX 网页编曲工作台：交互与实现规格

日期：2026-09-26。状态：**待实现的产品规格**，不是已完成功能说明。已合入独立调研复评与用户新增的和弦控制需求；采纳理由及实验修订见 [调研复评](research/RESEARCH_REVIEW_2026-09-26.md)。本文件是当前产品行为与验收的执行规格。

## 1. 产品目标与已核对的现状

FLUX 应让音乐创作者在浏览器中弹入一个想法，听见它，在独立轨道上试用生成结果，并通过叠加、静音、独奏判断是否值得保留。主要工作对象始终是可编辑的 MIDI 音符；默认流程不要求理解模型、token 或六种音乐变换。

本规格使用以下工作假设：首先支持桌面 Mac 浏览器；第一阶段是固定速度、固定拍号的短 MIDI 项目；单用户本地使用。项目速度、拍号、乐器与和弦控制是用户可见能力，不再硬编码为 120 BPM、4/4 和钢琴。实现细节可按验收与体验修订，已确认的输入、完整乐器、多轨与和弦需求保留。

2026-09-26 阅读源码确认：

| 位置 | 已有能力 | 距离目标的差距 |
| --- | --- | --- |
| `frontend/src/App.jsx` | 预填《小星星》、请求建议、接受/拒绝/重生成 | 只有 `notes` 与 `ghosts` 两个列表；接受后直接合并，无项目/轨道模型 |
| `frontend/src/PianoRoll.jsx` | SVG 音符网格、点击添删 | 固定 16 拍、48–84 音高、每拍一格、四拍一小节；不能播放、弹奏、录音、拖动 |
| `frontend/package.json` | React 与 Vite | 未引入音频引擎或 MIDI 编辑库 |
| `backend/main.py` | `/api/suggest` 接收 JSON 音符 | 返回随机示例建议；没有目标轨、音色、速度、拍号协议 |
| `research/pipeline.py` | 钢琴旋律条件 → AMT → MIDI/PNG/指标 | 固定抽取 program 0；输出合并后用于离线研究，不是多轨编辑协议 |
| `core/transforms.py` | 六种确定性音乐变换 | 可以作为选区编辑工具；不是使用生成器的必经步骤 |

### 成功条件

1. 不需要外接 MIDI 键盘，也能弹入并录下四小节旋律，随后回放和编辑。
2. 新生成内容始终可单独试听；接受、拒绝、重生成均不改变源轨音符。
3. 两条同音色轨仍可独立静音、独奏和调节音量；视觉叠加不影响归属。
4. 常用音色能快速选中，完整生成器乐器集合也有可搜索入口；不能将“全部支持”偷偷缩为几个预设。
5. 速度、拍号、录音时间、模型输入和 MIDI 导出的音乐位置一致。
6. MIDI 输入中的和弦自动显示；用户可手选根音、大小三和弦、add、sus 等，按上下文查看级数与和声进行，并用确认的和弦轨控制生成。

### 当前阶段的边界

先不实现音频录音、VST/AU 插件宿主、混音效果器链、自动化曲线、多人协作和移动端完整编辑。这些不是验证“输入 → 生成 → 对比 → 保留”所必需的。用户要求的完整乐器选择、键盘输入和多轨对比仍属于本轮产品方向，分阶段交付不等于取消。

## 2. 最直觉的主要流程

首次打开显示一个空的“旋律 1 · 钢琴”轨；示例旋律放到“载入示例”中，避免让用户以为页面上的内容是自己的作品。

1. 点击“启用声音”，音色加载完成后可直接试弹。
2. 顶部设置速度与拍号，默认 `♩ = 120`、`4/4`，无需先进入设置页。
3. 点击“电脑键盘”，屏幕底部展开带字母的琴键；默认仅试听，不写入项目。
4. 点击红色录音键，经过一小节倒数录入当前已准备录音的轨道。停下后出现可编辑片段。
5. 弹奏时键盘上方自动显示当前和弦候选；录入、导入或编辑后，在时间尺下显示和弦建议。确认建议或手动选择“根音＋类型”写入和弦轨；纯旋律可另点“建议配和声”。
6. 选定生成范围，点击“+贝斯 / +鼓 / +和弦铺底 / +钢琴伴奏 / 同音色变奏 / 接着写”。面板显示参考轨、和弦轨、目标角色与乐器；角色生成带对应默认音色，变奏／续写默认继承源轨音色。用户仍可显式选择同音色加层。
7. 结果显示在候选轨中，用“叠加 / 只听原轨 / 只听建议”三个试听按钮快速比较，也保留每轨 M/S。
8. 点击“保留此版本”，候选轨成为普通 MIDI 轨；点击“换一个”生成替代候选；点击“丢弃”移除候选。源轨始终在原处。

首个完整生成闭环是 **R0 和弦轨＋角色 pattern**：先开放贝斯、鼓和铺底；钢琴伴奏、变奏及续写按生成器能力开放，尚未支持的入口说明原因。贝斯默认指弹贝斯（program 33），鼓使用标准鼓组，铺底默认 warm pad（89），钢琴伴奏默认原声钢琴（0）。音色可改；角色决定写法，相同音色不代表相同角色。

六种变换放到选区的“变换”菜单中，按用户动作解释，例如“移高后重复”“倒影”“反向”“拉长”“缩短”“截取重复”。不要在主流程开头要求用户选择算法。

- 顶部运输控制始终固定，避免播放、录音藏在生成面板中。
- 轨道区决定“操作谁”；钢琴卷帘编辑选中的片段；生成面板决定“参考谁、生成什么”。三者各有清楚标签。
- 和弦行固定在时间尺下方，显示和弦名、时长、来源及可选的级数行；选中后展开“根音／类型／低音／范围”，不要求用户输入专业和弦符号。
- 首版可以限制一个轨道只有一个活跃片段，以减少编排复杂度，但数据结构使用片段，避免音符散落在整个项目。
- 音符改为单击选中、Delete 删除，减少当前“点一下就删掉”的误操作。保留绘制工具供连续输入。
- 保留/丢弃按钮只在有候选结果时显示；生成时展示实际状态、已耗时和取消，禁止并发重复提交。
- 候选同时用虚线、文字和颜色区分，不能只靠颜色。M/S/R 各有可访问名称、提示和选中状态；键盘能操作按钮与轨道列表。
- 默认收起调性、音域、密度等高级条件。目标乐器和参考轨不能藏入高级条件，它们直接影响生成结果归属。
- 窄窗口时生成面板改为抽屉，保留运输栏与编辑区域；先验证桌面 1280×800 和 1440×900，不承诺手机完整编曲。

## 4. 电脑键盘输入：具体键位、焦点和录音语义

### 4.1 与 Logic Musical Typing 对齐的部分

已检查 Apple 官方文字与键盘截图：白键为 `A S D F G H J K L ; '`；黑键为 `W E T Y U O P`；`Z/X` 降/升八度；`C/V` 降/升力度。Apple 还定义 `Tab` 延音、`1/2` 弯音、`3–8` 调制控制。[Apple Musical Typing 指南](https://support.apple.com/en-au/guide/logicpro/lgcpb19cbd34/mac)、[官方键盘布局图](https://help.apple.com/assets/697921A0B89A6DAE620D667A/697921A59331DF6F330EFA33/en_US/d0a6e56a1baa4f995423c60107da9f2c.png)。

FLUX 初始 A 键设为 MIDI 60；本项目显示为 C4，同时在提示中显示 `MIDI 60`，避免不同软件的八度编号习惯造成误判。

| 键 | 相对 A 键的半音 | 初始 MIDI 音高 |
| --- | ---: | ---: |
| A / W / S / E / D | 0 / 1 / 2 / 3 / 4 | 60 / 61 / 62 / 63 / 64 |
| F / T / G / Y / H / U / J | 5 / 6 / 7 / 8 / 9 / 10 / 11 | 65 / 66 / 67 / 68 / 69 / 70 / 71 |
| K / O / L / P / ; / ' | 12 / 13 / 14 / 15 / 16 / 17 | 72 / 73 / 74 / 75 / 76 / 77 |
| Z / X | 整体 −12 / +12 | 界面同步更新当前范围 |
| C / V | 力度降低 / 提高 | 建议每次 8，限定 1–127；步长是 FLUX 选择 |

首版实现音符、复音、八度和力度；延音需要项目能保存 CC64 事件后才开放录制。弯音与调制可后续加入，因为当前 AMT 转换器忽略它们，提前显示可录制控件会造成数据丢失。若做仅试听控制，必须明确显示其不会进入生成条件。

### 4.2 网页不能照搬全部桌面快捷键

- “电脑键盘”按钮是主要入口。不要默认劫持浏览器 `Cmd+K`；它在不同浏览器中可能已有用途。
- 只有显式进入演奏模式且焦点不在输入框、文本域、可编辑文本、下拉选项或对话框内，才捕获演奏键。
- 输入轨名、搜索音色、输入 BPM 和中文输入法组合输入期间，按字母不能发声或改谱。
- 采用 `KeyboardEvent.code` 的物理位置映射；非 QWERTY 布局显示说明与可见琴键标签。键盘布局 API 不是必须依赖。
- 默认让 Tab 保留网页焦点导航。提供显式“Logic 延音键兼容”开关后，才在演奏区域内捕获 Tab；Esc 一键退出并恢复正常导航。延音始终有可点击按钮。
- 不响应系统修饰键组合；忽略 `keydown.repeat`，避免长按产生密集重复音。
- 每个按键按下时存储当时的 `trackId + pitch + voiceId`；松开时释放同一个声音。演奏中改变八度，不得把 note-off 发给新的音高。
- 浏览器失焦、切标签、退出演奏、换轨、停止录音、组件销毁时统一释放悬挂音符并清理延音；保留“停止全部声音”应急按钮。
- 允许多键同时按下；电脑硬件本身的键位冲突可能限制可演奏和弦，应测试用户实际键盘，不能承诺无限同时按键。

### 4.3 三种输入模式

| 模式 | 音符何时写入 | 时间如何确定 | 默认行为 |
| --- | --- | --- | --- |
| 试听 | 不写入 | 立即发声 | 打开电脑键盘后的默认模式 |
| 实时录音 | 录音进行时写入已准备轨 | 按下决定开始，松开决定结束 | 一小节倒数，可关；录完作为一次可撤销操作 |
| 步进输入 | 明确开启后每组按键写入 | 编辑光标 + 所选固定时值 | 所有当前按下键释放后再推进一个步长，方便录入和弦 |

步进模式显示“时值 1/4、1/8、1/16、三连音”和“休止/前进一步”按钮，不复用 Musical Typing 中的音高键做不透明快捷键。实时录音的量化默认关闭；录完用户可选量化，保存原始事件时间，撤销可还原。对短到不足一个 tick 的合法按键赋至少 1 tick，不保存零时值音符。

录音仅记录当前准备轨；选中轨、准备轨、静音、独奏分别存储。首版限制一次只准备一轨，点击某轨 R 明确转移准备状态；选择另一轨查看不自动把录音转过去。试弹始终路由到准备轨（若存在），否则选中轨，并在键盘标题显示目标轨名。

### 4.4 和弦识别：弹入 MIDI 后自动可见

和弦控制随电脑键盘输入一起规划，不依赖外接设备。屏幕琴键、电脑键盘、MIDI 文件导入与后续 Web MIDI 使用同一套音符／和弦表示。

| 输入场景 | 自动显示 | 写入规则 |
|---|---|---|
| 试听中的多键演奏 | 当前音符和一个或多个可能的和弦名；支持转位显示，如 E–G–C → C/E | 只预览；点“写入选区”才建立和弦事件，未录音的试弹不改项目 |
| 实时录音／步进 | 弹奏时显示名称；停止或完成步进后，在实际音乐位置显示和弦建议 | 原 MIDI 照常保留；点“采用此处／采用选区建议”才成为生成控制 |
| 导入 MIDI／卷帘添删移动音符 | 对选中的音高轨和片段自动分析；更改后刷新相关建议 | 不将所有轨盲目合并，也不修改已确认和弦；鼓轨不参与音高和弦识别 |
| 只有单音或不充分的音程 | 显示音名／音程或“和弦未确定” | 不把连续单音的并集强行判为一个和弦；“建议配和声”是独立动作 |

即时识别只读输入状态，不阻塞发声。建议首轮使用约 80 ms 的聚合／稳定窗口，避免手指先后落下时标签快速跳变；该值是待键盘实测的交互参数，不延后 note-on，也不改变原录音 onset。步进以一组按键为单位；录音／导入按音符实际重叠、节拍边界和持续变化分段，不能把整小节所有 pitch class 合并成和弦。

同音跨八度去重用于和弦类型匹配，但保留最低实际音判断转位。手指释放、短暂过渡音和不完整 voicing 可以给出多个候选或“未确定”；例如 C–E–G–A 可解释为 C6 或 Am7/C，由上下文排序并允许手选。分解和弦只在有足够上下文时标“推测”，不冒充同时发声的确定和弦。后续支持 CC64 时须同时跟踪持键与延音状态，不能让踏板残留音把两个和弦错误拼成一个。

识别结果显示“明确匹配／多种解释／未确定”，分析得分只用于排序；未经标定不显示“95% 正确”之类概率。确认后的和弦与原音符编辑解耦：源 MIDI 改动时提示“输入已变化，可重新分析”，保留用户确认的控制。

### 4.5 手动固定和弦：根音＋类型＋可选低音

在和弦行选中时间范围，选择根音 C–B（含升降号）和类型，试听后写入。默认长度取选区；无选区时取当前光标起一小节，可拖动边界或在拍／小节输入框调整，支持一小节多个和弦和跨小节长和弦。预览使用临时声音，不自动生成或复制伴奏 MIDI。

首版选择器必须覆盖下列类型，不能把 add／sus 延后为只有文本输入的高级能力：

| 类型 | C 根音示例与构成 |
|---|---|
| 大三／小三／减三／增三 | C = C E G；Cm = C E♭ G；Cdim = C E♭ G♭；Caug = C E G♯ |
| 属七／大七／小七 | C7 = C E G B♭；Cmaj7 = C E G B；Cm7 = C E♭ G B♭ |
| 挂留 | Csus2 = C D G；Csus4 = C F G；sus 替换三音 |
| 加音 | Cadd9 = C E G D；Cmadd9 = C E♭ G D；Cadd11 = C E G F；保留三音，不自动添加七音 |
| 六和弦／扩展九和弦 | C6 = C E G A；Cm6 = C E♭ G A；C9 = C E G B♭ D；与 Cadd9 分开 |

“低音”可选根音、和弦内转位音或指定斜杠低音，如 C/E、C/G；低音不改和弦根音。增强扩展、变音组合以后扩展；遇到首版不支持的输入明确显示原因，不能静默降为大三和弦。和弦符号从结构化字段生成，同时保存用户选择的升降号拼写。

手选或确认即成为固定控制；自动识别、调性分析、LLM 都不能覆盖它。支持移动、改长、复制、删除和撤销；相邻事件使用左闭右开区间，不允许确认事件重叠。用户写入与已有事件冲突时，明确展示替换范围，确定后作为一个可撤销操作。

**空白不等于 N.C.。** 空白表示未指定和声；N.C. 是用户明确选择“无和弦”。R0 在 N.C. 区间不生成音高伴奏，鼓可按节奏继续；跨入 N.C. 的伴奏音在边界结束。已有旋律保持原样。纯鼓生成不要求先填写和弦。

### 4.6 上下文分析：调性、和弦级数与和声进行

和弦名描述当前结构，级数描述它在某个调里的关系。**不能从孤立的 C 和弦断定项目是 C 大调。** 用户可以选择／锁定项目调性；未指定时，根据前后和弦、旋律的时值与重音、终止走向提出调性候选，显示“推测 C 大调／A 小调”等可选解释。首版以全局调性分析；疑似转调区段显示“可能转调／待确认”，不强行套回全局自然音阶，局部调性编辑列后续能力。

在和弦行下自动显示级数序列与简短进行标签：

- 确认 C 大调后，C–G–Am–F 显示 **I–V–vi–IV（1–5–6m–4）**；Dm7–G7–Cmaj7 显示 **ii7–V7–Imaj7（ii–V–I）**。
- 相同 C 和弦在 G 大调显示 IV，在 F 大调显示 V；更改调性只改变分析，原和弦和 MIDI 不移调。
- C 大调中的 D7–G 可提示 **V7/V–V**；F–Fm–C 可提示 **IV–iv–I、借用小下属**。这是结合前后关系的解释，允许替代分析或“未确定”，不自动改和弦。
- C/E 的根音级数仍是 I，转位另显示 I⁶／三音低音；add、sus、七音信息保留，不能只显示根音数字丢掉和弦性质。

添加或修改前后和弦会重算受影响的分析；分析和用户选定的和弦分别保存。用户可纠正调性或选择备选解释；对称和弦、调式性片段或证据不足时保留歧义，不强制功能标签。P0 覆盖上述常见大小调进行与可解释的不确定状态；复杂连续转调不作为首轮准确率承诺。

实现先用本地确定性字典匹配、调性候选评分和序列规则；Tonal 的候选和弦名、music21 的调性相关 Roman numeral 可作参考／对照，尚未决定安装。自动分析不依赖网络 LLM。[Tonal 和弦 API](https://tonaljs.github.io/tonal/docs/groups/chords)、[music21 级数分析](https://music21.org/music21docs/usersGuide/usersGuide_23_romanNumerals.html)

### 4.7 和弦轨怎样控制生成

用户确认的和弦轨是共享的和声控制，默认自己不发声；“试听和弦”是临时预览。“生成和弦铺底”才创建可编辑 MIDI 轨。不要把控制轨自动混进播放、导出或新增候选，造成双重伴奏。

1. 请求冻结参考旋律、确认的和弦事件、调性及其状态、目标角色、选区与项目 revision。级数／进行是辅助解释；确定的实际和弦结构与低音是控制依据。仅有推测的标签不得悄悄作为确定事实传给模型。
2. R0 读取实际和弦与低音安排贝斯、铺底及声部衔接，鼓读取拍号、律动和和弦变化位置。铺底可跨小节保持，不用“每小节一定有新 onset”判断失败；贝斯尊重 C/E 的指定低音 E。
3. 支持原生和弦条件的模型由适配器直接编码；AMT 等仅接收音符条件的模型，可以将和弦展开成**专用条件音符**，连同旋律送入模型，保留来源且不作为生成输出。每个模型必须实测这种方式，不把接收 JSON 等同于已利用和弦。
4. 生成器声明和弦控制能力为“原生／条件音符／不支持”，并记录实际使用的事件。不支持的模型不能静默忽略和弦；界面说明限制，由用户明确选择无和弦的实验路径。
5. LLM 读取同一快照，规划角色、节奏型、音区、密度和声部连接，再调用生成器／R0。用户主动要求“重配和声”时，LLM 可以给出和弦变更候选，经用户采用后才改控制轨。Jev 可研究排序，但不负责逐键识别、级数计算或实时发声。
6. 和弦空白范围先提示补齐、确认“建议配和声”，或显式选择支持无和弦的生成器；R0 音高角色默认不猜 C 大调。输出只含目标选区内的新声部；强拍和弦关系用于诊断与角色策略，不把全部非和弦音、七和弦中的三全音或借用和弦一律禁止。
7. 修改和弦、调性或源音符后，旧请求响应标为 stale；现有候选标明其和声版本。保留过的 MIDI 不会自动重写，用户可以针对受影响范围重新生成和比较。应用候选前再次检查 revision。

“从旋律建议配和声”与“识别已弹出的和弦”分别验收。前者本来就有多解，可在 B 阶段先给少量规则候选；不要求它先达到可靠水平，才允许用户手动选和弦并生成。

## 5. 速度、拍号与可靠播放

### 5.1 项目时间模型

建议项目采用整数 tick，例如 `ppq=960` 表示每四分音符 960 ticks，速度明确表示四分音符 BPM。四分音符拍与拍号的分母不能混为一谈：

```text
每小节四分音符拍数 = numerator × 4 / denominator
每小节 ticks       = ppq × numerator × 4 / denominator
固定速度下的秒数   = ticks / ppq × 60 / quarterBpm
```

例：4/4 每小节 3840 ticks；3/4 为 2880；6/8 也是 2880，但重音分组、网格与拍号显示不同。6/8 默认按两组附点四分音符强调节拍；UI 始终写 `♩ =`，避免将用户输入误当成附点四分音符 BPM。

建议 BPM 输入范围 20–300，分母支持 2/4/8/16，分子支持 1–12；4/4、3/4、6/8 做快速预设。这些是首版产品范围，不是音乐标准的极限。录音期间锁定速度和拍号修改；停止后调整 BPM 保持音符 tick 位置和时值不变，仅改变播放时长。修改拍号保持 tick 位置不变，重新计算小节线，并提示“已有音符位置保持不变”。第一阶段不做速度/拍号变化图。

`core/` 的 `Fraction` 可在调用边界转换为 tick；若变换产生不能精确落在当前 PPQ 的有理数，明确报出或按用户量化选择处理，不能默默截断。AMT 使用 10ms 时间分辨率，项目事件送入模型时的量化损失应记录；保留源轨原始时间，不能将原轨经模型往返转换作为保存方式。

### 5.2 音频时钟与运输控制

首版具备播放/暂停、停止回到起播点、回到开头、移动播放头、范围循环和节拍器。录音到循环尾时首版停止，避免还没定义的循环覆盖录音行为。

播放调度使用 AudioContext 的时间；React 渲染和 `requestAnimationFrame` 只更新视觉播放头。若用周期性 JS 任务提前发送事件，必须给音频引擎传绝对播放时间；不能把 `setTimeout` 触发时刻当作音符落点。Tone.Transport 官方说明了这个时间参数的重要性。[Tone Transport](https://github.com/tonejs/tone.js/wiki/Transport)。

试听和录音的键盘事件使用单调时钟，并通过明确的映射关联到音频时间。外放/声卡延迟另行测量，不按猜测给所有事件减固定毫秒。停止、拖动播放头和循环回跳要处理 note-off、跨边界音符和队列取消；首版循环尾截断正在发声的音符，下一轮重新触发，并在行为说明中写明。

有 `getOutputTimestamp()` 时使用其 `contextTime/performanceTime` 映射事件与输出时间，并验证暂停／恢复后的映射；否则采用经测量的时钟映射和可选敲拍校准。保存原始事件时间，补偿仅应用一次；`outputLatency` 只是测量线索，敲拍偏移还包含用户演奏偏差，不直接当作纯设备延迟。[MDN 输出时间戳](https://developer.mozilla.org/en-US/docs/Web/API/AudioContext/getOutputTimestamp)

浏览器可能阻止未由用户手势启动的音频；第一次点击“启用声音”或播放时创建/恢复 AudioContext，并显示音源加载/失败状态。不能把“网格动了但无声”留给用户猜测。[MDN Web Audio 最佳实践](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)。

## 6. 音源与完整 MIDI 乐器目录

### 6.1 “乐器编号”与“声音资源”分开

MIDI program 是乐器类别标识，SoundFont/采样器是产生声音的资源，轨道是用户组织作品的对象。同一个 program 可出现在多条轨道上，同一组 MIDI 也可用不同 SoundFont 播放。换一个更好的音源可能改善音质，但不会修正音符和节奏杂乱。

本地已安装 AMT 的 `anticipation/config.py` 定义 `MAX_INSTR=129`：内部 `0–127` 是 128 种音高型乐器，`128` 是鼓类别。不要写成“128 种乐器再加第 129 个 GM program”；鼓应使用独立 `isDrum` 标记，常规 GM MIDI 导出到人类编号的第 10 通道（代码通常为 channel 9）。GM 规范入口见 [MIDI Association General MIDI](https://midi.org/general-midi)。

### 6.2 选择器

轨道名称下方点击音色打开抽屉：

- 顶部常用预设：原声钢琴、电钢琴、尼龙弦吉他、指弹贝斯、合成贝斯、弦乐、合成 Pad、标准鼓组。
- 下方“全部 MIDI 乐器”：按 GM 家族分类并支持中英文搜索，列出全部 128 programs 和鼓；不以“以后再做”隐藏稀有乐器。
- 可以使用 1–128 的展示编号，但内部保存 0–127；开发信息可显示内部编号，普通用户主要看到名称。
- 每项提供短试听；鼓轨显示 Kick/Snare/Hi-hat 等鼓件名与对应 MIDI note，而不是对鼓应用调内音阶过滤。
- 全目录可浏览不等于首屏下载所有采样；音源可按需加载，或下载一份完整 GM SoundFont。未加载、加载失败、已就绪要有清楚状态。
- 生成器能力与播放能力分别记录。若某模型只会钢琴，其他音色仍可手动编辑/试听，但生成按钮应解释限制；不能把输出改 program 后称为模型学会了该乐器写法。
- 在当前 AMT 下可以开放整个词表集合，但“编号可寻址”不等于每一种乐器都有可靠输出质量，需要用实验给出支持程度。

### 6.3 浏览器音频技术建议

| 候选 | 已核实能力与许可 | 对 FLUX 的位置 |
| --- | --- | --- |
| 原生 Web Audio + SpessaSynth | `spessasynth_lib` 与 core 当前采用 Apache-2.0；支持 SF2/SF3/DLS、MIDI 读写和浏览器合成 | **优先做小型验证**：完整 GM、鼓、多通道以及同音色独立轨更契合本项目。[官方仓库](https://github.com/spessasus/spessasynth_lib)、[core 许可](https://github.com/spessasus/spessasynth_core/blob/master/LICENSE) |
| Tone.js | MIT；提供运输时钟、合成器和效果器 | 适合作运输和节拍器；它本身不是包含全部 GM 乐器的采样库。引入后与合成器共享一个 AudioContext，避免两个时钟。[官方仓库](https://github.com/Tonejs/Tone.js) |
| smplr | MIT；包含预渲染 SoundFont 播放器和乐器列表 | 轻量候选，先验证鼓映射、资源下载、同音色独立控制、延音和 note-off，再决定是否替代完整 SF2 引擎。[官方仓库](https://github.com/danigb/smplr) |

SpessaSynth 的实时事件支持 `eventOptions.time` 传入 AudioContext 秒数，适合提前调度；官方建议优先复用一个合成器实例。轨道映射到独立合成通道，同 program 也不共用混音控制；实现时验证引擎动态通道与路由，不按轨道数无限创建引擎。[事件调度 API](https://spessasus.github.io/spessasynth_lib/synthesizer/basic-synthesizer/)、[WorkletSynthesizer](https://spessasus.github.io/spessasynth_lib/synthesizer/worklet-synthesizer/)。

**引擎许可不代表采样许可。**首轮音频验证可以使用用户本地选择的合法 SF2；确定内置音源前记录资源作者、来源、具体许可、再分发条件、文件大小和校验值。此处尚未选定、下载或捆绑任何音色库，不能承诺“装上库就拥有可发布的全部乐器采样”。

已核验的完整音色候选是作者维护的 **GeneralUser GS**：GM／GS bank，官方列 261 个音色预设及 13 套鼓组；仓库 SF2 文件元数据为 32,319,396 bytes，适合先测完整目录而非逐个拼凑采样。当前许可文件标 v2.0.3，允许用于个人／商业音乐创作及软件项目，同时作者明确记录部分历史采样来源的不确定性。因此可作为本地功能验证候选，正式捆绑时保留原许可、版本和来源说明并再次核验。它是通用试听音源，不等于 Logic 原厂音色或现代流行编曲质量保证。[作者仓库](https://github.com/mrbumpy409/GeneralUser-GS)、[作者许可原文](https://github.com/mrbumpy409/GeneralUser-GS/blob/main/documentation/LICENSE.txt)。

### 6.4 浏览器范围

电脑键盘输入使用普通浏览器键盘事件，发声使用 Web Audio；这两件事不依赖 Web MIDI。AudioWorklet 适合独立音频线程，在现代浏览器已广泛可用，部署时使用 HTTPS 或受信任本地开发上下文。[MDN AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)。

Web MIDI 用于外接键盘、虚拟 MIDI 端口或发送到其他软件，属于后续可选功能。2026-09-26 核对 MDN 兼容数据：Chrome 支持、桌面 Firefox 有额外权限流程，Safari 尚未支持；必须运行时检测 `requestMIDIAccess`，权限拒绝后电脑键盘仍能正常工作。[MDN Web MIDI](https://developer.mozilla.org/en-US/docs/Web/API/Web_MIDI_API)、[MDN 原始兼容数据](https://github.com/mdn/browser-compat-data/blob/main/api/Navigator.json)。

首轮实测覆盖用户 Mac 上的 Chrome 与 Safari：后者检验纯网页演奏与播放，不能用没有 Web MIDI 支持当作“不支持电脑键盘”的理由。

将 Safari 验证放在 A 阶段首次音频验证中；兼容列表未列出不能直接视为不支持。若需要替代引擎，仍验收完整 GM 目录、鼓与同音色独立控制，不以静默缩减乐器作为完成首版的条件。

## 7. 轨道、同音色建议与源旋律分离

### 7.1 用户提出的新建同音色轨是正确的交互方向

原轨保留，生成内容位于另一轨，支持叠加与 Mute/Solo，比把所有建议直接追加到一个 `notes` 列表更适合编曲。新轨复制的是乐器/音源设置，**不复制源轨 MIDI 音符**；否则叠加播放将使原旋律出现两遍。

建议在普通轨下面创建候选轨；变奏／续写或显式“同音色加层”继承源轨音色，角色生成使用第 2 节默认音色，均保持独立音量、M/S。候选显示为 Ghost，但本身就是独立轨道草稿。接受后仅改变其状态，不把内容合并回源轨。重生成替换同一候选位置，保留上一个候选供撤销；不同候选默认互斥试听，避免每点一次就增加一层声音。

### 7.2 但前端新建一轨不能单独解决模型输出边界

已读本地 `anticipation/sample.py`：当前 `generate()` 在返回前通过 `ops.split(tokens)` 分开普通事件与 controls。当前 pipeline 使用 `inputs=None`，因此可以在合并前直接取得生成 accompaniment；不必先合成 MIDI 再按音高差集猜哪些来自用户。

问题发生在随后 `pipeline.run()` 的 `ops.combine(accompaniment, controls)`，以及 AMT `compound_to_midi()` 按 `track_idx[instrument]` 创建输出轨：两组同 program 内容会被聚到同一乐器轨，源轨身份随之丢失。AMT note token 编码的是 program 与 pitch，不是 FLUX 的任意轨道 ID。

具体实现应做到：

1. 源轨原始音符保存在项目中，作为唯一事实来源；生成请求使用它的快照。
2. 生成器适配器单独返回新增事件和候选 ID，在任何展示用混合之前保留来源。
3. 客户端把新增事件放入新 `trackId`，可以与源轨具有相同 `program`。
4. MIDI 导出由项目结构创建独立轨、通道和 program；不调用会按 program 合并身份的路径导出整个作品。
5. 若更换模型且其 API 返回整个“输入 + 输出”，适配器必须根据官方生成边界/事件来源拆分，并为同音色同音高重叠写测试；按音高去重会误删合法齐奏。
6. “不再次塞入源 controls”与“模型不模仿原旋律”是两个不同问题。前者通过数据流保证；后者属于模型音乐质量，不能靠新建轨保证。

MIDI 文件中独立 track 也不自动带来独立 MIDI 通道。为了同音色两轨独立混音，播放通道必须分离；标准 MIDI 1.0 单端口通道数有限。首版限制可同时导出的独立音高轨数量并清楚提示；多鼓轨合并至鼓通道或多端口导出属于明确的后续决策，不静默丢轨。

### 7.3 Mute、Solo、录音准备的确定规则

| 状态 | 规则 |
| --- | --- |
| 选中 | 决定当前编辑对象；不改变播放 |
| R 录音准备 | 决定录入目标；首版最多一轨；候选轨须先保留才能录入 |
| M 静音 | 停止该轨播放；保持音符数据与生成参考状态 |
| S 独奏 | 任一轨 Solo 时只播放 Solo 且未 Mute 的轨；支持多轨 Solo |
| M 与 S 同时开 | 本产品规定 Mute 优先；用一致的按钮与提示表示 |
| 生成参考 | 显式选择的轨道快照；不随临时 Mute/Solo 自动变化 |

“只听建议”等快捷试听只临时改变监听组合，退出比较时恢复之前的 M/S；避免试听动作无意影响下一次生成的参考轨。

## 8. 数据与 API 合同建议

现有 `{notes} → {ghosts}` 不足以承载新需求。旧注释中“接模型时协议不变”的假设需要被本规格替代。先定义一个简单、可序列化的数据模型，再实现 UI：

```text
Project
  id, schemaVersion, revision, ppq, quarterBpm, timeSignature, loopRange
  keyContext?, chordTrack[], tracks[], generations[]
KeyContext
  tonicPc, tonicSpelling, mode: major | minor
  source: user | inferred, status: suggested | confirmed
ChordEvent
  id, startTick, durationTick, kind: chord | no_chord
  chord?: rootPc, rootSpelling, quality, additions[], bassPc?, bassSpelling?
  source: manual | midi_detected | harmonized
  status: suggested | confirmed, sourceNoteIds?, sourceRevision?
Track
  id, name, role, program, isDrum, soundbankId, volume, pan, mute, solo
  clips[]
Clip
  id, startTick, lengthTick, status: committed | candidate
  origin: user | generated | transformed, generationId?
  notes[]
Note
  id, pitch, startTick, durationTick, velocity
Generation
  id, requestId, projectRevision, inputHash, harmonyHash
  generatorId, generatorVersion, weightsHash?, seed?, params
  status: pending | ready | stale | failed | cancelled
  timings, diagnostics, ratings?
```

`selectedTrackId`、`armedTrackId`、播放状态、即时和弦预览属于编辑会话状态；音符起点相对片段，片段与和弦起点相对项目。持久和弦事件中的 `quality` 使用受控字典，`additions` 表示加音；根音／低音为 0–11，拼写与音级一致，构成音由字典计算，符号不是另一套可独立修改的事实。N.C. 无 chord 字段；suggested 事件不进入生成控制。确认后保留来源，仅显式重新采用才替换。

上下文分析是可重算的派生结果：`analysisVersion, inputRevision, chordId, keyCandidates, romanCandidates, progressionLabels, certainty`；不作为可覆盖和弦事件的事实字段。换版本或输入变化时使其失效。项目 JSON 保存确认的调性、和弦及来源；普通 MIDI 文件没有本项目完整的和弦控制契约，首版只保证音符／tempo／拍号／轨道 round-trip，和弦以项目 JSON 无损保存，不能默默把控制轨展开为伴奏音符。

生成请求只取选中的参考范围，不把浏览器音频节点等运行时对象传到后端。音乐编辑、和弦／调性／生成范围改变推进 revision；M/S、监听音量等不改变生成输入的操作不使候选失效。

建议生成请求包括：

```text
requestId / projectRevision
project: ppq, quarterBpm, timeSignature
referenceTracks: 带稳定 ID、program、isDrum 的片段快照
range: startTick, endTick
task: add_role | vary | continue | transform
target: program, isDrum, role
harmony: 确认的 chordTrack 范围快照（含跨选区边界的事件）, keyContext?
harmonyAnalysis: 可选的级数／进行解释及不确定状态
harmonyHash / inputHash / generatorId
seed（可选）
```

响应包含独立候选内容、实际 seed/模型 ID、请求耗时、有效生成时长和可读失败原因。内部诊断记录约束、实际使用的和弦快照与编码方式、解析丢弃事件数、模型时间分辨率、输出来源；普通界面只显示用户需要知道的状态。请求返回时若参考轨或和弦／调性已经改变，候选标为 stale，不能自动加入或覆盖当前作品；已取消任务的迟到响应丢弃。同一目标一次只运行一个请求，重新生成须先取消当前请求。

AMT 适配还要处理现有限制：`melody_to_controls()` 当前只接受 program 0；生成终点错取末音 onset，首 50 ms controls 被裁掉；AMT event 编码移除输入 velocity，重建统一力度且忽略 CC/pitchwheel/time signature。因此新的原轨保存、播放、导出必须绕开这个有损往返，和弦条件音也要通过首音可见性测试。生成力度先采用显式的角色 pattern 策略，记录为后处理，后续独立评估模型力度建模。

|---|---|---|
| CH-01 | 试听按下 MIDI 60、64、67；再用 52、55、60 | 自动显示 C、C/E（允许备选）；没有录音／确认时项目不变；note-on 不等待识别 |
| CH-02 | 步进录 C；导入含同时发声 C 和弦与依次单音 C–D–E 的片段 | 前者显示建议并可采用；后者不将整段硬判为和弦；鼓不参与识别 |
| CH-03 | 输入 C–E–G–A；快速换和弦、松键、失焦 | 保留 C6／Am7/C 等合理备选；不残留上一组活动音；低把握不伪报确定结论 |
| CH-04 | 逐一选择 §4.5 的根音与类型，选择 C/E；拖动时长 | 所有列出的类型可选择／试听；Cadd9 无七音，C9 有 B♭，sus 不含被替换三音；低音与根音分开 |
| CH-05 | 确认 C 大调，输入 C–G–Am–F 和 Dm7–G7–Cmaj7；把 C 的调性改为 G 大调 | 前两组显示 I–V–vi–IV、ii7–V7–Imaj7；C 变 IV；和弦与源 MIDI 不变 |
| CH-06 | 在 C 大调上下文输入 D7–G、F–Fm–C；另输入无上下文孤立和弦 | 前两组提供副属／借用解释；孤立和弦不自动锁定唯一调性；解释可纠正 |
| CH-07 | 确认／手选和弦后改源 MIDI，再重新分析；对和弦编辑撤销重做 | 提示来源已变化，但已确认事件不被覆盖；撤销精确还原控制与确认状态 |
| CH-08 | 保存项目 JSON、重新打开；更改 BPM／拍号；导出 MIDI | 和弦结构、低音、拼写、来源、调性无损；改 BPM／拍号不改事件 tick；MIDI 不意外多出控制音轨 |
| CH-09 | C–G–Am–F 生成 R0 贝斯，再将 C 改 C/E | 根音型 pattern 各段首音为 C/G/A/F；C/E 首音为 E；新轨独立，源旋律不变 |

| CH-11 | AMT 假采样器检查条件与输出；给不支持和弦的模型发请求 | 和弦／旋律 controls 真正进入上下文且不重复出现在新增候选；不支持条件时不静默成功；LLM 不改确认和弦 |
| CH-12 | 生成时修改和弦／调性；取消另一个任务；已保留候选后改和弦 | 旧响应 stale，取消响应丢弃；已保留 MIDI 不变并可选择重新生成；仅 M/S 切换不使请求 stale |

识别与分析性能目标：目标 Mac 上，在稳定窗口结束后，单组识别 UI 更新 p95 ≤100 ms；4／8 小节停止录音后的分析 p95 ≤500 ms，记录音符数和设备。先用固定字典／上下文样例做确定性验收，再对实际演奏测误判、多解与手动修改率；这些是待测目标，不是现有性能。

建议性能目标，均为**待测的工程门槛**：在目标 Mac 与内建音频设备上，暖启动后键盘事件到音频调度的 p95 小于 20ms；调度误差与真实听觉延迟分别测量，不能用前者冒充后者。8 轨、每轨短循环持续播放 5 分钟，UI 操作不造成卡音或逐渐漂移。记录浏览器、声卡、采样率、音色资源和是否蓝牙输出；先不承诺模型生成 2 秒内完成。

产品验收覆盖两条路径：新建 → 90 BPM / 4/4 → 键盘录四小节 → 确认识别的和弦或手选 add／sus → 查看级数进行 → R0 贝斯／铺底 → 原/建议/叠加对比 → 保留 → 项目保存与 MIDI 导出；同时保留同音色候选的独立比较路径。至少使用五个不同输入重复，全部不需改代码或手工搬文件。是否提高创作质量另由模型评估与开发者试听判断。

## 10. 实现阶段与依赖

### A. 可听、可弹、可保存的 MIDI 工作台

先确认 AudioContext + GM 合成器小型验证：两条同音色轨、鼓、准确 note-off、独立 M/S、调度时间戳、Safari/Chrome、完整乐器资源方案。通过后实现项目数据、运输栏、BPM/拍号、键盘试听与录音、卷帘编辑、项目文件保存。随后完成和弦自动显示、手动根音＋类型／低音编辑、常见上下文级数／进行及 CH-01–CH-08。这个阶段无需真实模型，测试候选明确标为测试。

### B. 和弦驱动的 R0 与候选轨

建立新请求协议，冻结源轨与和弦控制，生成事件在合并之前分离；角色优先面板、同音色候选、试听与接受/拒绝/重生成形成完整路径。先接 R0 两种原创风格的贝斯／鼓／铺底，完成 CH-09–CH-12，再加入从纯旋律建议配和声和开发者盲听模式。和弦识别不需等待模型，手动和弦也不需等待自动配和声。

### C. 音乐质量与控制

E0 的适配与日志可随 A/B 准备；完成后按调研复评的 E1/E2 比较 AMT、MIDI-GPT 等，并将达标模型接入同一个接口。钢琴续写独立研究，LLM 读同一和弦轨作编曲规划；约束失败、条件不支持和空输出有明确反馈。和弦控制在前两阶段完成，不以模型试验推迟。

### D. 扩展输入与高级编辑

外接 MIDI、延音/表情、六种变换菜单、候选历史、较大项目与更复杂的 MIDI 交换。对用户当前方向最重要的电脑键盘、完整乐器入口和同音色对比已在前面完成。

不按日历承诺工期；每阶段以验收样例和可操作演示结束。最先影响实现的未决项：

| 未决项 | 负责角色 | 何时必须决定 | 当前建议 |
| --- | --- | --- | --- |
| 内置 GM 音色文件与再分发条款 | 工程/项目负责人 | 将资源加入发行包之前 | 先用合法本地 SF2 验证，再选体积与许可适合的完整库 |
| 播放音频引擎 | 工程 | A 阶段小型验证结束 | SpessaSynth 优先，Tone.js 是否必要由时钟实现复杂度决定 |
| 第一种模型生成任务与模型 | 研究/工程 | C 阶段真实模型接入前 | B 已用 R0 跑通角色生成；模型先按角色与 R0 比较，保留同音色能力 |
| 第一批流行乐风格范围 | 项目负责人/研究 | 正式数据准备前 | 将“流行乐”细化成可听可比较的目标，例如流行钢琴伴奏或流行节奏组 |
| 导出独立轨上限及多鼓轨策略 | 工程 | MIDI 导出上线前 | 在单端口可表达范围内明确限制，不静默合并源轨身份 |
